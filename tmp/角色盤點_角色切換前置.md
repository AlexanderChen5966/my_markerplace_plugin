## 1. 結論

- **6 個角色都可以用現有零件組起來**（App 工程師、網頁前端、教授做研究、教授備課、UI/UX 設計師、個人創作）；盤點後又加了行銷策略、創新創業，共 8 個，見第 8 節
- **教授兩個角色早就有現成的工具包**：`~/Desktop/紀錄文件資料夾` 的 `notebooklm-v2.1.2-kit`（研究，14 個 skill，免金鑰；API key 線 `notebooklm-v2.0.2-kit` 當備案）與 `notebooklm-teaching-v1.1-kit`（備課，19 個 skill），設計給「只用對話框」的教授在 Codex desktop／Claude Desktop 執行。角色直接引用工具包，不重新組 skill
- 缺的不多：網頁前端沒有 TypeScript LSP；UI/UX 缺一份「去 AI 味」的檢查規則
- **App 工程師和網頁前端有八成重疊**。建議拆成「共用的開發包＋各自的平台包」，不要做成兩份幾乎一樣的清單
- **公司資訊要隔離**：slc plugin、Atlassian、公司 Figma 檔、b2b 專案的 hook 只在兩個工程師角色載入；教授與設計角色一律不載入
- 原本沒有歸屬的零件（Blender、Godot、Pixelorama、點讀筆、電子書閱讀器）歸到新的「個人創作」角色

## 2. 角色組成方式

一個角色 = **共同層** ＋ **一到多個功能包** ＋ **該角色專屬的 MCP／連接器** ＋ **排除清單**。

```
共同層（所有角色都有）
  ├─ 開發包 ──┬─ App 平台包     → App 工程師
  │          └─ Web 平台包     → 網頁前端
  ├─ 研究包（notebooklm-v2.1.2-kit）        → 教授做研究
  ├─ 教學包（notebooklm-teaching-v1.1-kit） → 教授備課
  ├─ 設計包                    → UI/UX 設計師
  └─ 創作包                    → 個人創作
公司包（slc、Atlassian）只掛在兩個工程師角色
```

三層記憶**不屬於任何角色**：記憶是「你」，角色是「工作方式」，所有角色都讀同一份記憶。

### 3.8 設計包（UI/UX 設計師）

**用途**：製作或更新畫面、做圖、做 icon，**去除 AI 味**。公司畫面、自己的作品、side project 都用（2026-11-09 使用者補充）；只有改公司畫面時才加公司的 Figma 檔與該 repo 的 DESIGN.md。所以這個角色的重點不是「會畫」，而是「畫出來不像模板」：

- **以專案的 `DESIGN.md` 為準**：色彩、字型、間距、元件都用該專案的 token，不用模型預設的配色與字型
- **frontend-design** 是 Anthropic 官方針對這件事寫的 skill（說明寫「避免看起來像模板預設值」），列為必載
- **缺一份「去 AI 味」檢查規則**：例如不用紫藍漸層、不用 emoji 當圖示、不每區塊都卡片加陰影、不用置中大標題＋三欄功能卡的固定版型、文案不寫空泛形容詞；畫面完成後用 Claude in Chrome 截圖逐條對照。這份規則要新寫（見第 5 節）
- 中文文案可借教學工具包的 humanize-zh 觀念（去除 AI 腔調）
