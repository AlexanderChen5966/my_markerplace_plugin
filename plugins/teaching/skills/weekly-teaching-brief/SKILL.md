# weekly-teaching-brief

論文版用 `daily-brief-generator`（每日）。**教學版改成每週**——備課的節奏是週，
不是日：這週要上哪個單元、下週要出什麼考卷、這批作業什麼時候改完。

每天問「今天有什麼新素材」對備課沒有意義。

## 使用方式（純對話）

```
週報
這週要教什麼
備課進度
現在狀況
```

建議每週固定時間跑一次（週五收尾或週日備課前）。

---

## 需要的輸入

第一次執行時問一次，之後記在 `outputs/<課號>-<term>/schedule.md`：

```
我需要知道你的課表才能排週報：

1. 這學期教哪幾門課？
2. 每門課的單元順序與週次？（可以只給大概）
3. 今天是第幾週？

之後我會自己算，不用每次問。
```

## 設計原則

### 1. 「需要你做的」放最前面（第三節的第一項）

教師時間有限。統計數字放最後——那是給人有空時看的，不是行動項。

### 2. 分「AI 做不了的」與「AI 可以做的」

`fact_checked`、rubric 調整、回饋審核、術語選擇 —— 這四類**只有教師能做**，
要明確分出來，並說明為什麼不能代做。

其餘的（整理教材、產教案、渲染投影片）AI 可以做，直接問「要現在做嗎」。

### 3. 主動催課後回顧

`teaching-backflow` 的最大敵人是遺忘。上完課超過 3 天還沒回顧就要主動提醒，
超過 7 天要說明代價：

```
⚠️ U04 上完 9 天了，課後欄位還是空的。

老實說再拖就記不清了——「哪個環節失敗、為什麼」這種細節，
一週後回想通常只剩「好像還可以」。

要現在花 5 分鐘嗎？我一次問一題。
```

### 4. 用剩餘週數製造時間感

期中考、期末考、報告截止日倒數，讓教師知道現在該開始什麼。

「期中考還剩 3 週，題庫還沒開始」比「題庫未完成」有用得多。

### 5. 不要每週都報全部統計

統計數字只報**變化量**（本週 +2）。沒變化的項目不佔版面。

---

## 不要做的事

- **不要把統計放前面**
- **不要列出所有能做的事**。只列這週真正要做的（跟課表對得上的）
- **不要用「加油」「繼續努力」這類話**。教師要的是清單，不是激勵
- **不要幫教師決定優先順序之外的事**。標出來、給建議、他決定
