# slide-builder

## 為什麼用 Marp 而不是直接產 pptx

**Markdown 是單一真相源。** 直接生成 pptx 會得到一個二進位黑箱，改一個字要重跑整個生成、
無法 diff、無法版控、無法回灌 wiki。

Marp 的 `.md` 原稿可以 git diff、可以被其他 skill 讀取、可以隨時重新渲染成 pptx 或 pdf。

**例外**：必須套校方 `.potx` 模板時（系上要求統一格式），Marp 做不到——
Marp 的版面由主題決定，無法套校方母片。這時交棒 `office-export`（用 python-pptx）。
原稿仍留 Markdown，pptx 當渲染產物，流程不變。

## 使用方式（純對話）

```
第三單元做投影片
把教案轉成 ppt
投影片改成 pdf 給我
```

## 執行步驟

### 1. 從教案抽取結構

教案的環節 → 投影片段落：

| 教案環節 | 投影片 |
|---------|-------|
| 封面 | 1 張（`_class: title`）|
| 學習目標 | 1 張 |
| 導入問題 | 1-2 張 |
| 講述主線 | 每個概念 1-2 張 |
| 活動指令 | 1 張（必須自成一張，學生要看著做）|
| 收束 | 1 張 |
| 預告 | 1 張 |

**60 分鐘課約 12-18 張。** 超過 25 張通常是把講稿貼上去了。

### 2. 三條版面硬規則

**規則一：一張投影片一個訊息。**

投影片上有兩個並列的重點 → 拆成兩張。學生一次只能接收一件事。

**規則二：條列 4 項上限、層級最多 2 層。**

超過 4 項 → 拆張，或改成表格，或改成圖。

**規則三：活動指令自成一張，且必須能一次讀懂。**

指令超過三句話，課堂上一定有人做錯。寫完自己讀一遍：「如果我是學生，看完這張知道要做什麼嗎？」

### 3. 中文字型（硬規則）

**必須套 `templates/marp-theme-zh.css`。** 不得依賴預設主題。

```markdown
---
marp: true
theme: teaching-zh
paginate: true
---
```

字型堆疊已在主題內建：`PingFang TC` → `微軟正黑體` → `Noto Sans TC` → `思源黑體`。

⚠️ **不指定會 fallback 成難看的替代字型，投在牆上全班都看得出來。**
這不是美感問題，是可讀性問題——後排學生看不清楚。

**渲染前檢查**：目標電腦有沒有這些字型？若投影片要在教室公用電腦播，
建議一併輸出 PDF（字型已嵌入），避免現場字型缺失。

### 4. 講者備忘稿

每張投影片下方用 Marp 的 HTML 註解寫備忘稿：

```markdown
## 市場區隔的四個變數

- 地理
- 人口
- 心理
- 行為

<!--
講到這裡要停一下，問：「你們覺得哪一個最常被誤用？」
預期答人口變數。若沒人答，直接說「大部分教科書都從人口開始，
但那通常是最偷懶的切法」——這句是要鋪陳下一張的迷思。

★ 這裡主動點破 [[misconception-MKT101-區隔等於分類]]：
「分完之後要問三個問題：找得到嗎、買得起嗎、反應不一樣嗎。」

時間：這張約 4 分鐘。超過 5 分鐘就要跳過心理變數的細節。
-->
```

備忘稿要寫：**要說的話（口語）、時間、若學生沒反應的備案、要點破哪個迷思。**

備忘稿是「要照著講出口的話」，所以**必須口語化**——見下一步。

### 5. 去 AI 味（`--slides` 模式）

文案與備忘稿掛 `humanize-zh --slides`：

| 套用 | 不套用 |
|------|-------|
| A 組（用詞句法禁止清單）| B 組（結構禁止模式）|
| C 組（節奏、長短句）| |
| D 組（加人味，用在備忘稿）| |

**為什麼不套 B 組**：投影片的結構化、條列、制式是**優點**——學生要能掃讀抄筆記。
套「不要每次都用條列」會毀掉投影片。

**為什麼文案要去味**：字少所以爛字更刺眼。「賦能學生的行銷思維」投在牆上，
全班都知道是 AI 寫的。

**為什麼備忘稿最要去味**：那是你要照著講的話。AI 腔的句子念起來會卡，
因為它的節奏不是人講話的節奏。

### 6. 渲染

```bash
# pptx（可再手改、可加動畫）
marp --theme templates/marp-theme-zh.css \
     outputs/MKT101-2026F/slides/MKT101-U03.md \
     -o outputs/MKT101-2026F/slides/MKT101-U03.pptx

# pdf（字型已嵌入，教室公用電腦最保險）
marp --theme templates/marp-theme-zh.css \
     outputs/MKT101-2026F/slides/MKT101-U03.md \
     --pdf --allow-local-files \
     -o outputs/MKT101-2026F/slides/MKT101-U03.pdf
```

**Markdown 原稿與渲染產物放同一資料夾**，方便對照。渲染產物不手改
（手改了下次重新渲染就沒了）。

### 7. 事實檢查閘門

🛑 **標 `[待查證]` 的內容不得進投影片。**

投影片是直接投給全班看的，錯誤數據會被幾十個學生抄進筆記。渲染前檢查：

```
🛑 無法渲染。第 8 張引用了 MKT101-U03 摘錄第 7 條，該條標 [待查證]
   （來源是自動字幕，數字可能有誤）。

   請先核對，或把那張改成不含具體數字的說法。
```

## 工程師一次性安裝

```bash
npm install -g @marp-team/marp-cli
```

PDF 輸出需要 Chromium（marp-cli 會自動下載，或指向系統 Chrome）。

驗證：`marp --version` 有輸出即可。

## 不要做的事

- **不要把教案整段貼上投影片**。投影片是提示，不是講稿
- **不要一張塞兩個訊息**
- **不要用預設主題**（中文會很醜）
- **不要手改渲染產物**（改 Markdown 原稿）
- **不要放 `[待查證]` 的內容**
- **不要在備忘稿寫書面語**。那是要念出來的
