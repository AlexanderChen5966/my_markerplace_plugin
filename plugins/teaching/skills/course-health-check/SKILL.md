# course-health-check

論文版 `wiki-health-check` 每月跑一次。教學版改成**每學期兩次**：
開學前（檢查準備度）與期末（檢查累積與缺口）。

理由：課程的週期是學期。每月檢查一門課沒有意義，該檢查的是「這門課下學期能不能更好教」。

## 使用方式（純對話）

```
行銷管理健檢
這門課還缺什麼
期末檢查一下
開學前檢查
```

---

## 兩種模式

| 模式 | 時機 | 重點 |
|------|------|------|
| **開學前** | 學期開始前 2-4 週 | 準備度：教材齊不齊、教案有沒有、換版影響 |
| **期末** | 學期結束後 | 累積度：回顧填了嗎、迷思有沒有進庫、明年要改什麼 |

自動判斷：問教師「現在是開學前還是期末？」，或依 `term` 與當前日期推測後確認。

---

## 開學前健檢：八項檢查

### 1. 課綱涵蓋率

比對 `raw/living/` 的課綱 vs `wiki/unit-notes/` 現有條目。

```
課綱 16 週，已整理教材 12 個單元。

缺口：
  🔴 W07 消費者決策歷程 — 無教材、無條目
  🔴 W13 品牌權益 — 無教材、無條目
  ⚠️ W15 期末報告週 — 無條目（可能不需要，確認一下？）
  ⚠️ W16 彈性週 — 同上

→ W07、W13 需要在上到之前補齊。W07 是第 7 週，剩 6 週準備時間。
```

### 2. 教學產出完整度

| 單元 | ODEP | 教案 | 投影片 | 題庫 | rubric |
|------|:---:|:---:|:---:|:---:|:---:|
| U01 | ✓ | ✓ | ✓ | ✓ | — |
| U02 | ✓ | ✓ | ⚠️ 未渲染 | ✓ | — |
| U03 | ✓ | 🔴 | 🔴 | ✓ | ✓ |

**rubric 那一欄的判斷**：只有需要評分作業的單元才需要 rubric。
不要把「沒有 rubric」一律當缺失——先問這個單元有沒有要交作業。

### 3. 事實核對狀況

```bash
grep -rl 'fact_checked: false' wiki/unit-notes/ outputs/
```

```
🔴 6 個條目 fact_checked: false，共 14 條未核對摘錄

其中 3 條來自自動字幕（transcript_quality: auto），風險最高——
中文自動字幕的專業術語常出錯。

優先核對：即將上到的 U05、U06（各 2 條）
```

### 4. 對齊檢查（呼叫 `objective-alignment-check`）

課程層級的對齊問題，不只單元層級：

```
🔴 期末考範圍涵蓋 U08-U14，但 U13 完全沒出題（U13 教了 2 週）
⚠️ 全學期評鑑層目標 5 個（占 36%），但評量只有期末一題申論（占 15%）
⚠️ U03 術語混用（投影片用 4C、考題用 4P）
```

### 5. 過期與換版（呼叫 `stale-check`）

```
⚠️ 4 個檔案過期（你 8/1 改了 U03 講義）

換版檢查：
  raw/fixed/ 的課本是 2024 年第 15 版
  → 若這學期改用第 16 版，14 個單元全部要重做（可分批）
  → 但 misconceptions/ 的 7 個條目不受影響 ✓
```

### 6. 迷思庫處理狀況 ★

```
迷思庫 7 個條目：

⚠️ 需要結構性調整（frequency ≥ 3）：
  [[misconception-MKT101-區隔等於分類]] — 4 學期
  [[misconception-MKT101-定位就是廣告]] — 3 學期

  這兩個連續出現代表教法或教材編排問題。建議這學期各做一次結構性調整
  （不是換活動，是改講述順序或教材結構）。

✓ 已改善：
  [[misconception-MKT101-越細越好]] — 2026S 改教法後從 42% 降到 18%，
  這學期先維持現做法觀察。

⚠️ 未掛回 D 層：
  [[misconception-MKT101-市占率誤解]] 沒有掛在任何單元條目的 D 層
  → 備課時看不到它，等於白建。要掛到哪個單元？
```

第三項是很容易發生的失效：**迷思建了但沒掛回去，等於躺在資料夾裡等人想起來。**

### 7. 隱私掃描（呼叫 `privacy-guard`）

```
🛑 outputs/MKT101-2025F/feedback/ 有 3 份仍為 reviewed_by_teacher: false
   （2025 秋季的，應該是那學期沒審完就結束了）
   → 建議刪除或封存。未審核的回饋留著是風險。

⚠️ raw/living/MKT101-U06-案例.md 沒有 license 標記
   這份看起來是從商業雜誌抄的，要確認能不能發給學生。

✓ 未發現學號格式殘留
✓ 未發現對照表誤入 vault
```

### 8. 跨學期資產累積

```
本課累積（教了 3 個學期）：

  單元條目 14 / 合成條目 4 / 迷思 7 / 教學反思 9

  ✓ 健康：迷思與反思都在成長，代表回灌流程有在運作

  ⚠️ 但 U09-U14 完全沒有 teaching-lesson
     → 這 6 個單元教了三年，卻沒留下任何經驗紀錄。
       通常代表這幾週剛好在期末，忙到沒回顧。
       建議：這學期把回顧排進行程，一上完就寫。
```

第二項是本 skill 最有洞見的檢查：**看出哪些單元「教過但沒累積」**，
而那通常有系統性原因（期末太忙、代課、線上課）。

## 期末健檢：四項檢查

### 1. 課後回顧完成率

```
14 個單元，已回顧 9 個。

未回顧：U05, U09, U11, U12, U14
  U14 是上週的，還記得 → 建議現在補
  U05 是三個月前的，可能記不清了 → 若真忘了就標「未回顧」，不要編
```

### 2. 本學期新增資產

```
✓ 新增 3 個 teaching-lesson（2 有效 / 1 無效）
✓ 新增 2 個迷思條目
✓ 6 個單元的 P 層已依實際經驗更新
✓ 1 個迷思經教法調整後明顯改善（42% → 18%）
```

### 3. 明年要改什麼（給下學期的自己）

彙整所有 `teaching-lesson` 的「下次調整」欄位 + 對齊問題 + 高頻迷思，
產出一份 `outputs/<課號>-<term>/next-term-todo.md`：

```markdown
# MKT101 下學期待辦（2026F 產出）

## 結構性調整（優先）
1. U03 把「有效區隔四條件」提到變數分類之前講
   理由：連續 4 學期的「區隔等於分類」迷思源自課本編排順序

## 教案調整
2. U03 案例改短（800 字 → 400 字），活動時間才夠
3. U07 加一題申論（目前評鑑層目標沒被評量）

## 待補
4. W07、W13 教材仍未整理
5. U09-U14 這學期沒回顧，下學期一上完就寫
```

**這份檔案是期末健檢最重要的產出。** 下學期開學前的健檢會先讀它。

### 4. 封存

該學期最後版本移入 `archive/<term>/`，`_versions/` 對應清理。

---

## 判定與回報格式

```
🔴 必須處理（會影響上課）
⚠️ 建議處理（影響品質或累積）
✓ 健康
```

**最多列 5 項 🔴。** 超過 5 項時只列最緊急的 5 個，其餘歸「還有 N 項，要看嗎」——
一次丟 20 個待辦事項，教師會直接放棄。

---

## 不要做的事

- **不要自動修改**。健檢是診斷，不是治療
- **不要把「沒有 rubric」一律當缺失**。先問這單元有沒有要交作業
- **不要一次列出所有問題**。最多 5 項紅色
- **不要在期末健檢時逼教師補三個月前的回顧**。記不清就標「未回顧」，編出來的回顧比空白更糟
- **不要把 `_versions/` 計入條目統計**
