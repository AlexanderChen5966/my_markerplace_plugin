# teaching-backflow

論文版有 `paper-knowledge-backflow`：論文結案後把審稿攻防經驗回灌 wiki，避免知識隨專案流失。

教學版的對位問題更嚴重：**上完一堂課學到的東西，如果不寫下來，一個月後就忘光。**
明年再教同一單元，等於從零開始——而你明明已經知道哪個活動會爆掉。

這個 skill 就是接住那些東西。

## 使用方式（純對話）

```
第三單元上完了，回顧一下
上週的課哪裡沒講好
teaching-backflow MKT101-U03
這學期結束了，整理一輪
```

---

## 執行步驟

### 1. 讀取課後欄位

來源：`outputs/<課號>-<term>/lesson-plans/<unit_key>.md` 的「課後填寫」段落。

若教師還沒填 → **不要自己編**，改成訪談式對話，一次問一件事：

```
來回顧第三單元。我一次問一件事，你想到什麼就說，不用完整。

1. 實際時間跟計畫差多少？（計畫是導入10/講述20/活動20/收束8/預告2）
```

教師回答後才問下一題。**不要一次丟五個問題**——那樣教師只會回「還好」。

五個必問：
1. 實際時間 vs 計畫
2. 哪個環節有效
3. 哪個環節失敗、為什麼
4. 學生卡在哪
5. 下次要改什麼

### 2. 分流到三個去處

| 內容 | 去哪 | 為什麼 |
|------|------|-------|
| 學生卡住的地方、錯誤模式 | `misconception-miner` → `wiki/misconceptions/` | 迷思要累積 frequency |
| 活動成效、時間配置、教法判斷 | `wiki/teaching-lessons/` | 教學經驗資產 |
| 具體的教案修正 | 回寫 `wiki/unit-notes/` 的 P 層 | 下次備課直接生效 |

**三個去處都要走，不是選一個。** 只寫 teaching-lessons 不回寫 P 層，明年備課時還是看不到。

### 3. 建立 teaching-lesson 條目

`wiki/teaching-lessons/teaching-lesson-<term>-<簡短描述>.md`

```markdown
---
title: 用失敗案例反推教市場區隔，比先講變數有效
unit_keys: [MKT101-U03]
course: 行銷管理
term: 2026S
type: teaching-lesson
status: processed
verdict: 有效                   # 有效 | 無效 | 部分有效 | 待再試
level: level/undergrad
tags: [course/marketing, topic/segmentation, type/teaching-lesson]
---

## 做了什麼

原本按課本順序：先講四個區隔變數，再講有效性條件。
2026S 改成：先給一個「切錯的市場」案例，讓學生自己找出問題，再回頭建立條件。

## 結果

- 「區隔等於分類」的錯誤率從 60% 降到 42%
- 但活動時間超支 8 分鐘，講述被壓縮
- 學生反應：課後有 3 人主動來問延伸問題（去年 0 人）

## 為什麼有效（我的判斷）

先看到失敗，學生才有「原來分類不夠」的需求感。
按課本順序講時，條件是「多出來的知識」；反推時，條件是「解決問題的工具」。

## 代價

活動要 28 分鐘（原計畫 20）。要砍掉原本的第四個變數細講，改成自己讀。

## 下次調整

- 案例改短一點（原案例 800 字太長，改 400 字）
- 一分鐘紙條當場檢核，不要等課後作業才知道
- 保留反推順序 ✓

## 相關

- 迷思：[[misconception-MKT101-區隔等於分類]]
- 單元：[[MKT101-U03]]
- 教案：outputs/MKT101-2026S/lesson-plans/MKT101-U03.md
```

**「代價」這一段不可省略。** 每個有效的教法都有成本（時間、深度、備課負擔）。
只記好處不記代價，明年照抄就會踩到同樣的時間爆掉問題。

### 4. 回寫 ODEP 的 P 層與 D 層

**P 層**：把驗證過的教法寫進時間表與環節細節，標註來源學期。

```markdown
| 30-58 | 活動 | 失敗案例反推（2026S 驗證有效，錯誤率 60%→42%）| 案例（400 字版）|
```

**D 層**：新迷思掛 wikilink，並更新「預估認知負荷」若實際與預估不符。

### 5. 更新迷思條目的「有效的教法」表格

在對應 `misconceptions/` 條目的表格 append 一列：

```markdown
| 2026S | 改用「失敗案例反推」 | 60% → 42% ✓ |
```

### 6. 學期末批次回顧

```
這學期結束了，整理一輪
```

批次處理該學期所有單元，並產出學期總結：

```
2026S 學期回顧（行銷管理，14 個單元）

已回灌：11 個單元
未填課後欄位：3 個（U05, U09, U12）——要現在補嗎？

本學期新增：
  ✓ 4 個 teaching-lesson（3 有效 / 1 無效）
  ✓ 2 個新迷思條目
  ✓ 6 個單元的 P 層已更新

⚠️ 需要注意：
  [[misconception-MKT101-區隔等於分類]] 已連續 4 學期出現
  → 建議下學期做結構性調整，不只是換活動
  → 我在 misconception-miner 那邊有具體建議，要看嗎？

下學期備課時，這 11 個單元的教案會直接帶著今年的經驗。
```

## 不要做的事

- **不要編造課後心得**。教師沒填就訪談，訪談不到就留空並標「未回顧」
- **不要一次丟五個問題**。一次一題，教師才會給具體答案
- **不要只記成功**。失敗的嘗試同樣有價值——記下來才不會明年又試一次
- **不要省略「代價」**
- **不要只寫 teaching-lessons 就結束**。沒回寫 P 層等於白做
- **不要把個別學生的表現寫進條目**。只記模式
