# humanize-zh

## 核心判斷：這份產出該不該去 AI 味

**不是全域套用。** 套錯反而更糟。

| 產出 | 模式 | 為什麼 |
|------|------|-------|
| 學生個別化回饋 | `full` | 人對人的文字。AI 腔讓學生覺得「老師用機器打發我」 |
| 家長／學生信件、課程公告 | `full` | 同上 |
| 推薦信 | `full` | 這封信代表你的判斷，AI 腔會削弱可信度 |
| 教學反思、送審的教學計畫書 | `full` | 要讓人相信是你的真實經驗 |
| **投影片文案與講者備忘稿** | `--slides` | 字少所以爛字更刺眼；備忘稿要照著講，AI 腔念起來會卡 |
| **投影片版面與條列結構** | `off` | 學生要能掃讀抄筆記，制式反而好 |
| **教案、rubric、題庫、雙向細目表** | `off` | 要的是結構化、可掃讀、窮盡列舉 |

🛑 **對 rubric 套用「條列 3-4 項上限」會讓級距漏掉。** 這是最容易犯的錯。
被要求對 rubric 去 AI 味時，要說明原因並拒絕：

```
rubric 不建議去 AI 味。

rubric 要的正是制式、窮盡、可掃讀——四級描述必須平均詳細，
套「條列上限」會讓「發展中」和「待改進」寫得草率，
而實際評分時大量落在那兩級。

如果你覺得 rubric 讀起來太生硬，我可以改的是：把描述從抽象改具體
（「論證深入」→「至少討論兩層因果並指出一個反例」）。這是清晰度問題，不是 AI 味問題。
```

## 執行步驟

### 1. 判斷模式

看檔案路徑與 `type:`：

| 路徑 | 模式 |
|------|------|
| `outputs/**/feedback/` `outputs/**/comms/` | `full` |
| `outputs/**/slides/` | `--slides` |
| `outputs/**/assessments/` `outputs/**/lesson-plans/` | `off` + 說明理由 |
| `wiki/teaching-lessons/` | `full` |

### 2. 套用規則（詳見 `refs/ai-flavor-zh-checklist.md`）

| 模式 | A 組用詞句法 | B 組結構 | C 組節奏 | D 組加人味 |
|------|:---:|:---:|:---:|:---:|
| `full` | ✅ | ✅ | ✅ | ✅ |
| `--slides` | ✅ | ❌ | ✅ | ✅（僅備忘稿）|
| `off` | ❌ | ❌ | ❌ | ❌ |

**A 組高頻詞快篩**（可先 grep 定位）：

```
進行～的動作｜對於～而言｜在～的過程中｜值得注意的是｜不僅…而且
隨著～的發展｜賦能｜打造｜助力｜聚焦於｜至關重要｜綜上所述
深入淺出｜循序漸進｜多元豐富｜具有～性
```

標點：破折號當停頓、粗體濫用、標題冒號結構化、驚嘆號、中英文間缺空格。

### 3. D 組：加人味（最關鍵）

去掉 AI 特徵只是消極面。真正讓文字像人寫的是**加入只有這個人寫得出來的東西**。

在教學情境的具體做法：

| 技巧 | 例子 |
|------|------|
| 寫實際碰過的事 | 「上次這題全班有一半算錯，錯在同一個地方」＞「這是常見錯誤」|
| 老實寫不順利的 | 「我第一次教這單元用三個案例，時間爆掉，現在只留一個」|
| 補背景與契機 | 「今年改教法，因為去年期末有學生說看不出這跟實務的關係」|
| 術語補說明＋比喻 | 抽象 → 具體 → 比喻，三層次 |
| 預先處理卡點 | 「你可能會想問為什麼不用 B 方法，因為…」|

🛑 **但不可編造。** 沒發生過的師生互動不能寫。若沒有真實素材可加，
就只做 A/C 組的減法，並告訴教師：

```
A 組與 C 組改完了。D 組（加人味）我沒動——
那需要你的真實經驗，我編不出來也不該編。

如果你想讓這段更有你的味道，可以補一句「去年這個活動的實際狀況」，
我幫你接進去。
```

### 4. 回饋類的反向護欄（不可違反）

`outputs/**/feedback/` 去味後**必須仍保留**：

1. **rubric 面向對應** — 哪一段對應哪個評分面向
2. **作品具體位置引用** — 第幾段、第幾題
3. **不加教師沒說過的主觀評價** — 「我覺得你不夠用心」這種話不可生成
4. **不編造師生互動** — 「記得你上次課後來問我」

**判斷準則**：去味後把文字給另一位老師看，他要能從文字反推出評分依據。反推不出來就是磨掉了。

改完後自檢並回報：

```
✓ 12 份回饋去味完成

護欄檢查：
  ✓ 12/12 份保留 rubric 面向對應
  ✓ 12/12 份保留作品位置引用（第幾段）
  ✓ 未加入主觀評價
  ✓ 未編造互動

改了什麼：
  - 移除「值得注意的是」×8、「進行分析」×5、破折號 ×14
  - 拆掉 6 處三句以上的長句
  - 學生C 那份的第二段原本很繞，改成兩句短的
```

### 5. 自我檢查

改完依序問：

1. A 組禁用詞掃過了嗎？
2. 條列超過 4 項、層級超過 2 層嗎？（`full` 模式才查）
3. 有至少一個「只有我寫得出來」的具體細節嗎？
4. （回饋類）評分依據還在嗎？
5. **念一遍。念得卡的地方就是還有 AI 味的地方。**

第 5 條最有用。書面看不出來的生硬，念出來立刻現形——這也是為什麼講者備忘稿一定要去味。

## 不要做的事

- **不要對 rubric、題庫、細目表去 AI 味**（要說明原因）
- **不要為了「有人味」編造經驗或互動**
- **不要磨掉回饋的評分依據**
- **不要一律套全套規則**。先判斷產出類型
- **不要把「刪掉粗體和破折號」當成完成**。那只是 A 組，沒有 D 組就還是像 AI 寫的
