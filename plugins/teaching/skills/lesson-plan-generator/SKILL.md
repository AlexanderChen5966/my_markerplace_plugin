# lesson-plan-generator

把單元條目展開成「拿著就能上課」的教案。

## 使用方式（純對話）

```
產出行銷管理第三單元的教案
這週的課幫我寫教案，60 分鐘
MKT101-U03 教案，這次是 EMBA 班，改成 3 小時
```

---

## 執行步驟

### 1. 讀取 ODEP 條目與確認參數

必問（若教師沒說）：

| 參數 | 為什麼要問 |
|------|-----------|
| 課堂長度 | 60 / 90 / 180 分鐘，時間表完全不同 |
| 學期（term）| 決定寫到 `outputs/<課程>-<term>/` 哪個資料夾 |
| 學生層級 | 大學部 / 研究所 / EMBA 的活動設計差很多 |

**同一單元不同層級要產不同教案**，但共用同一份 ODEP 條目。
檔名：`<unit_key>.md` / `<unit_key>-exec.md`。

### 2. 目標與 Big idea 原封不動搬過來

O 層的 Big idea 與學習目標**一字不改**地搬到教案。

理由：教案是 ODEP 的執行版，不是重新詮釋版。若教師覺得目標該改，
應該改 ODEP 條目再重新產教案，而不是在教案裡偷偷改——否則兩邊會漂移。

### 3. 時間分配

**硬規則：時間總和 = 課堂長度。**

配置建議（60 分鐘課）：

| 環節 | 建議佔比 | 說明 |
|------|:---:|------|
| 導入 | 15% | 拋必問問題，建立需求感 |
| 講述 | 35% | 不要超過。單向講述超過 25 分鐘學生就掉線 |
| 活動 | 35% | 學生實際動手／討論 |
| 收束 | 10% | 形成性評量 + 回應迷思 |
| 預告 | 5% | 銜接下週 |

**講述超過 40% 時要主動提醒**：

```
⚠️ 這份教案講述佔了 55%（33 分鐘）。
   單向講述超過 25 分鐘，學生注意力會明顯下滑。
   建議把「四個區隔變數」的後兩個改成小組自己讀 + 上台講，可省 8 分鐘。
```

### 4. 逐環節細節

**導入**必寫「若全班沒反應怎麼辦」。這是最常發生的實況。

**講述**必須把 D 層的已知迷思**主動排進去**：

```
講到「區隔準則」時，明確說：
「很多人以為區隔就是把客戶分類，但分類完如果找不到、或找到了不肯付錢，
　那個區隔就沒有商業意義。」
→ 對應 [[misconception-MKT101-區隔等於分類]]
```

**主動點破迷思比等學生自己撞牆有效。** 這是 D 層存在的目的，不要只掛在條目裡不用。

**活動**的指令必須「能一次講清楚」——寫成可以直接投影的一段話。
指令超過三句話的活動，課堂上一定會有人做錯。

### 5. 鷹架與差異化

至少寫弱／強兩檔 + 缺課補救。

不要寫「依學生程度調整」這種空話，要寫具體給什麼：
- 弱：給檢核表、給半成品、減少變數數量
- 強：給取捨題、給反例、要求同時滿足衝突條件

### 6. 風險與備案

三個必列風險：時間不夠、學生沒讀教材、設備故障。

每個風險要寫**徵兆**（在第幾分鐘看到什麼就知道要啟動備案），不只寫備案。

### 7. 預留課後回填區

教案結尾固定留「課後填寫」段落，欄位不可省略。
這一段是 `teaching-backflow` 的輸入來源，也是教案跨學期價值的來源。

### 8. 寫入與快照

路徑：`outputs/<課號>-<term>/lesson-plans/<unit_key>.md`

**若檔案已存在** → 先呼叫 `version-keeper` 建立快照，再覆寫。

frontmatter 必帶 `source: wiki/unit-notes/<unit_key>.md` 與 `source_hash`，供 `stale-check` 用。

## 不要做的事

- **不要在教案裡改學習目標**。要改就回頭改 ODEP 條目
- **不要規劃超時的內容**。時間加總不等於課堂長度就是錯的教案
- **不要寫「依情況調整」**。備案要具體到能直接執行
- **不要省略課後回填區**。省掉它，這份教案明年就只是一份靜態文件
