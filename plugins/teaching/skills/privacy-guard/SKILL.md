# privacy-guard

教學情境跟研究情境最大的差別：**會碰到學生的個人資料。**

論文版 kit 的所有檢查都是 advisory（提醒但不阻斷），因為論文出錯最多是引用不準。
教學版這一道**必須阻斷**——個資一旦送出第三方服務就收不回來，即使之後刪除也可能已被快取。

完整規則見 `refs/privacy-rules.md`。本檔是執行流程。

## 使用方式（純對話）

```
這批作業可以收進來嗎
幫我把學生名字去掉
這份能上傳 NotebookLM 嗎
檢查一下 vault 有沒有個資
```

---

## 四道檢查

### 檢查一：入庫去識別化（`raw/` 寫入前）

**觸發**：任何素材要進 `raw/`，且符合以下任一徵兆：

- 檔名含「學生」「作業」「成績」「名單」「繳交」「出席」「輔導」
- 內容出現：姓名欄位、學號格式（如 `B1234567`）、email、電話、分數欄位
- 是 zip 或資料夾，內含多個以人名命名的檔案（典型的 LMS 批次下載）

**動作**：

1. 掃出所有可識別欄位，列給教師確認
2. 逐一替換：姓名／學號 → `學生A` `學生B` `學生C`（按檔案順序，不按成績順序）
3. 特殊個資（身心障礙、家庭狀況、宗教、醫療）**一律移除，不概化保留**
4. 自由文本中的間接洩漏（「我爸在台積電當廠長」）→ 標出來請教師判斷是否遮蔽
5. **對照表不寫進 vault**。輸出到終端讓教師自己抄，或存到 vault 外的路徑，並明確告知：

```
對照表如下，請自己保管，我不會寫進 vault：
  學生A = 王小明
  學生B = 李小華

理由：對照表 + 去識別化資料放一起 = 完整個資，等於沒去識別化。
```

**阻斷條件**：教師拒絕去識別化 → 不入庫。可以建議「那這批就不進 vault，你直接看原檔」。

---

### 檢查二：NotebookLM 上傳白名單

**觸發**：任何 NotebookLM 上傳動作前（`notebooklm-skill` 會呼叫本檢查）。

**白名單制——清單以外一律拒絕，不做例外判斷**：

| ✅ 允許 | 🚫 禁止 |
|---|---|
| 出版教科書 PDF | 學生作業、作答、考卷 |
| 課綱、課程大綱 | 成績、名單、出席紀錄 |
| 教師自製講義、投影片 | 課堂錄音、錄影 |
| 公開網頁教材、公開 YouTube | 親師溝通、輔導紀錄 |
| 期刊論文、法規 | 任何含對照表的檔案 |
| 去識別化且**經教師逐份確認**的學生作品範例 | 已去識別化但**未逐份確認**的學生作品 |

**阻斷時的回應**（要說清楚原因，不要只說「不行」）：

```
🛑 這份不能上傳 NotebookLM。

檔案：outputs/MKT101-2026F/feedback/U03-回饋初稿.md
原因：含學生作答內容。上傳 = 送第三方服務，即使之後刪除也可能已被快取。

替代做法：
  你要問的是「這批學生共同弱點在哪」對嗎？
  這件事用 misconception-miner 在本機做就好，不需要上傳。
```

---

### 檢查三：授權與再散布標記

**觸發**：第三方素材入庫時、教材產出引用第三方內容時。

`raw/` 中第三方素材 frontmatter 必帶：

```yaml
license: "課本｜授權教學使用"
redistributable: false
attribution: "Kotler, P. (2024). Marketing Management. Pearson."
```

**衍生物繼承**：由 `redistributable: false` 素材衍生的教材，也帶 `false`。

**產出時檢查**：若一份要發給學生的講義引用了 `redistributable: false` 的內容 →

```
⚠️ 這份講義的第 2、5 段來自課本（redistributable: false）。

可以：課堂投影展示（合理使用範圍，依校方規定）
不可以：改寫成講義發給學生、放進學生可下載的課程包

建議：把那兩段改成「參見課本 p.78-85」，或自己重寫。
```

**特別盯 YouTube 逐字稿**：抓下來備課研究沒問題，但 AI 生成教材時會很自然地把逐字稿內容
融進去、看起來像原創。這是最容易不小心越線的地方，產出時要主動檢查。

---

### 檢查四：人工審核旗標

**觸發**：`outputs/**/feedback/` 與 `outputs/**/comms/` 的任何匯出、渲染、寄送動作。

```yaml
reviewed_by_teacher: false     # ★ false 一律阻斷
```

**阻斷回應**：

```
🛑 這 12 份回饋還沒經過你審核（reviewed_by_teacher: false），不能匯出。

AI 輔助 ≠ AI 評分。請逐份看過、改過之後告訴我「這批我看過了」，
我再把旗標改成 true 並匯出 docx。

要現在一份一份看嗎？我可以逐份顯示，你說改哪裡我就改。
```

**不接受批次放行**：教師說「全部都 OK」時，仍要確認：

```
確認一次：這 12 份你都逐份看過了嗎？
（AI 寫的回饋常有「聽起來對但其實錯」的評語，尤其是計算類作業。）
```

教師再次確認後才批次改 `true`。

## 全庫掃描

```
檢查一下 vault 有沒有個資
```

掃描項目：

| 項目 | 掃法 |
|------|------|
| 學號格式殘留 | `grep -rEn '[A-Z][0-9]{7,9}' wiki/ outputs/ raw/` |
| 常見姓名欄位 | `grep -rn '姓名\|學號\|座號' wiki/ outputs/` |
| 對照表誤入 vault | `grep -rn '學生[A-Z] *= *' .` |
| 缺授權標記的第三方素材 | 檢查 `raw/fixed/` 對應條目是否有 `license:` |
| 未審核的回饋 | `grep -rl 'reviewed_by_teacher: false' outputs/` |

輸出一份清單，標明每項的嚴重度（🛑 立即處理 / ⚠️ 建議處理），不自動修改。

---

## 設計原則

1. **阻斷但要給替代方案**。純粹說「不行」會讓教師繞過工具，那更危險
2. **不做聰明的例外判斷**。白名單就是白名單。「這份應該還好吧」是出事的開頭
3. **對照表永不進 vault**。這條沒有例外
4. **若學校有 AI 使用政策，那份優先於本 kit**
