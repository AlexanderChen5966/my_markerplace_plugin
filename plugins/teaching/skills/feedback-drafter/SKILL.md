# feedback-drafter

## 兩道前置閘門（都不可跳過）

### 閘門一：作業必須已去識別化

學生作業進 `raw/` 前必須跑過 `privacy-guard`。若偵測到未去識別化的姓名學號：

```
🛑 這批作業還有學生姓名（12 份中 12 份）。
   先跑 privacy-guard 去識別化，我才能處理。
```

### 閘門二：rubric 必須已經教師調整過

```
🛑 這份 rubric 的 adjusted_by_teacher 還是 false。

用未調整的 rubric 寫回饋，會產出「聽起來合理但不符合你標準」的評語，
你逐份改的時間比自己寫還久。先調 rubric，再回來寫回饋。
```

---

## 使用方式（純對話）

```
依 rubric 幫這批作業寫回饋初稿
第三單元案例分析的回饋
```

## 執行步驟

### 1. 逐份對照 rubric

每份作業對每個評分面向產出：

```markdown
### 學生A

**區隔基礎判讀**（對應目標 1）
- 級別：熟練（3）
- 依據：第 2 段正確指出採用行為變數 ✓；但未討論可觸及性（rubric 卓越級要求）
- 回饋：你抓到了行為變數這個關鍵，這部分判讀很準。往上一級的話，
        還需要問「這群人找得到嗎」——第 2 段如果補一句通路推論就完整了。

**風險識別**（對應目標 1）
- 級別：發展中（2）
- 依據：提到一個風險（成本），但未連結到區隔基礎本身的問題
- 回饋：……
```

**每條回饋必須可追溯到 rubric 面向與作品的具體位置。**（第幾段、第幾題、哪一行）

### 2. 三條撰寫硬規則

**規則一：只描述作品，不評價學生。**

| ❌ 不可 | ✅ 可 |
|---|---|
| 你不夠用心 | 第 3 段的論證跳過了中間步驟 |
| 你的分析能力有待加強 | 這份分析停在描述現象，還沒進到解釋原因 |
| 明顯是趕出來的 | 第 4、5 段只有結論沒有依據 |

理由：評價學生無法申訴、也無法改進。描述作品才能指出下一步。

**規則二：每個扣分點都要給下一步。**

指出問題後必須接「怎麼往上一級」。只說哪裡錯不說怎麼改，學生下次還是一樣。

**規則三：不產出分數。**

```
我可以寫「這個面向落在熟練級」並說明依據，
但最終分數與級別確認由你決定——AI 對複雜思考的評估還不可靠，
尤其是計算類與論證類作業。
```

### 3. 掛去 AI 味

回饋屬「人對人的文字」，套 `humanize-zh` **全套**規則。

**但要遵守反向護欄**（見 `refs/ai-flavor-zh-checklist.md`）：

去味後**必須仍保留**：
1. rubric 面向對應（哪一段對應哪個評分面向）
2. 作品的具體位置引用（第幾段）
3. 不可加入教師沒說過的主觀評價
4. 不可編造師生互動細節（「記得你上次課後來問我」這種）

判斷準則：**去味後把文字給另一位老師看，他要能從文字反推出評分依據。** 反推不出來就是磨掉了。

### 4. 寫入並上鎖

`outputs/<課號>-<term>/feedback/<unit_key>-回饋初稿.md`

```yaml
reviewed_by_teacher: false     # 🛑 阻斷匯出
```

### 5. 交回教師審核

```
✓ 12 份回饋初稿完成
  outputs/MKT101-2026F/feedback/MKT101-U03-回饋初稿.md

級別分布（僅供參考，最終由你確認）：
  卓越 1 / 熟練 5 / 發展中 4 / 待改進 2

🛑 reviewed_by_teacher: false —— 還不能寄。

我建議先看這 3 份：
  - 學生C：作品有創意但偏離題目要求，我不確定你會怎麼判
  - 學生G：計算過程有一步我看不出對錯，需要你確認
  - 學生K：可能有抄襲跡象（第 3 段風格與其他段落明顯不同），請你判斷

要一份一份看嗎？你說改哪裡我就改。
```

**主動標出「AI 判斷不可靠」的個案**是本 skill 最有價值的部分：
偏離題目要求、計算對錯不確定、疑似抄襲、文化脈絡相關的內容。這些一定要教師看。

## 人工審核完成後

教師說「我看過了」時，**再確認一次**：

```
確認一次：12 份你都逐份看過了嗎？

（我問這句是因為 AI 寫的回饋常有「聽起來對但其實錯」的評語，
　尤其計算類作業。批次放行的風險是錯的評語直接寄到學生手上。）
```

確認後：
1. `reviewed_by_teacher: true`
2. 可匯出 docx（記得指定中文字型）
3. 記錄審核日期

---

## 不要做的事

- **不要產出最終分數**
- **不要在 `reviewed_by_teacher: false` 時匯出或渲染**
- **不要為了口語化而模糊評分依據**
- **不要編造師生互動**
- **不要批次放行不再確認**
- **不要評價學生的人格、態度、努力程度** —— 你看不到那些，只看得到作品
