# rubric-builder

## 使用方式（純對話）

```
幫我做第三單元案例分析的 rubric
這份報告的評分標準
rubric-builder MKT101-U03 案例分析
```

---

## 執行步驟

### 1. 從學習目標反推評分面向

**面向必須對應 O 層的學習目標。** 這是硬規則。

```
學習目標（來自 MKT101-U03）：
  1. （分析）能判斷案例採用的區隔基礎並指出風險
  2. （評鑑）能評估兩個區隔方案並提出取捨理由

→ 評分面向：
  ✓ 區隔基礎判讀（對應目標 1）
  ✓ 風險識別（對應目標 1）
  ✓ 方案取捨論證（對應目標 2）
  ✓ 表達清晰度（通用面向）
```

🛑 **對不上任何目標的面向要刪掉。** 那代表在評不打算教的東西。

常見的錯誤面向：
- 「格式正確性」占 20% ← 除非格式是學習目標，否則這是在評「聽不聽話」而非能力
- 「參考文獻數量」← 數數量不是評品質
- 「創意」← 除非目標寫了 Bloom 創造層，否則學生不知道你要什麼

### 2. 產出 4 級描述

四級：卓越（4）／熟練（3）／發展中（2）／待改進（1）。

**硬規則一：禁用模糊詞。** 出現以下詞即需重寫：

| 禁用 | 改成 |
|------|------|
| 品質好、很好、優秀 | 說出「好」的具體特徵 |
| 深入、有深度 | 「至少討論兩層因果，並指出一個反例」 |
| 完整 | 「涵蓋四個變數中至少三個」 |
| 清楚 | 「每個主張後接一個具體證據」 |
| 適當、恰當 | 「引用來源與主張直接相關」 |
| 有創意 | 「提出課堂未討論過的應用情境」 |

偵測到模糊詞時要**當場改掉並說明**，不要產出後才提醒：

```
第一版寫了「論證深入」，我改成：
「至少討論兩層因果（為什麼會 A → A 為什麼導致 B），並指出一個反例」

理由：「深入」你我理解不同，助教理解又不同，同一份作業會給出不同分數。
```

**硬規則二：級距必須是程度差異，不是有無差異。**

❌ 壞（在數數量）：
- 卓越「有引用文獻」／熟練「引用較少」／發展中「幾乎沒引用」／待改進「沒引用」

✅ 好（在評品質）：
- 卓越「引用直接支撐主張，並指出文獻間的不一致」
- 熟練「引用支撐主張，但未處理相互矛盾處」
- 發展中「有引用但與主張關聯鬆散」
- 待改進「引用與主張無關，或僅堆疊來源」

**硬規則三：發展中與待改進要寫得出來。**

AI 傾向把「卓越」寫得很詳細、「待改進」寫得很草率（因為它在想理想答案）。
但實際評分時大量落在下面兩級。要求四級篇幅相當。

### 3. 權重與換算

面向權重加總 100%。權重要與課堂投入時間、Bloom 層次相符——花最多時間教的能力，權重最高。

分數換算表放在教師版，**不放學生版**。

### 4. 產出學生版

**作業公布時就要給學生 rubric**（TILT 透明化原則）。

學生版 = 四級描述，去掉權重與換算細節。

理由：學生看得到 rubric 才知道往哪努力。藏著等打分數是不公平的，
而且會收到一堆不知道方向的作業，改起來更累。

### 5. 標記待教師調整

```yaml
status: draft
adjusted_by_teacher: false
```

🛑 **`false` 的 rubric 不得用於實際評分。** 回報時要明確講：

```
✓ 初稿完成，4 個面向 × 4 級

⚠️ 這是初稿，級距一定偏離你的實際標準——AI 不知道你這門課「熟練」長什麼樣。
   請至少調整一輪，特別是「熟練」與「發展中」的分界（實際上最多人落在這裡）。

調完告訴我，我把 adjusted_by_teacher 改成 true 並產出學生版。
```

### 6. 寫入

`outputs/<課號>-<term>/assessments/<unit_key>-rubric.md`

檔案已存在 → 先呼叫 `version-keeper` 快照。

## 校準建議（給有助教的課）

多人評分時，rubric 寫得再好也會有落差。建議流程：

1. 抽 3 份作業（好／中／差各一），教師與助教**各自獨立**評分
2. 比對差異，找出對哪一級的理解不同
3. 把差異寫進 rubric 的級距描述（這是最有效的 rubric 修正方式）
4. 再抽 2 份驗證落差是否縮小

這一步本 kit 不自動化——它需要真人討論。但可以幫忙記錄校準結果並更新 rubric。

---

## 不要做的事

- **不要產出後才提醒模糊詞**。當場改掉並說明理由
- **不要把「待改進」寫得比「卓越」草率**
- **不要幫教師決定權重**。列建議與理由，教師決定
- **不要在 `adjusted_by_teacher: false` 時產出學生版**
